# 중계 프로그램 (relay)

사내망 리눅스 서버에 붙는 길을 만드는 작은 프로그램이다. **쓰는 사람이 자기
VDI 에 하나씩 깐다.**

챗봇 서버는 사내망 서버에 직접 붙지 못한다. 이 프로그램이 챗봇 서버로
**들어가는 방향 하나만** 써서 할 일을 받아 오고 결과를 올린다. 그래서
방화벽에 구멍을 내지 않는다.

```
   [브라우저] ──► [챗봇 서버]  ◄── POST /api/relay/poll ── [VDI: relay.exe] ──ssh──► [사내 서버]
                                 (할 일 있으면 바로, 없으면 25초 기다림)
```

화면이 없다. 웹이 조종하는 PuTTY 한 대다.

**한 사람에 한 대다.** 내 중계는 내 일만 받아 간다. 남의 중계가 붙어 있어도 내
일을 대신 해 주지 않고, 내 중계가 남의 일을 가져가지도 않는다. 서버에는 **내
VDI 에 있는 키**로 붙으므로 서버 쪽 계정 권한이 내 것 그대로다.

---

## 1. 준비물

| 무엇 | 왜 | 확인 |
|---|---|---|
| OpenSSH 클라이언트 | 키 인증으로 붙는다 | `ssh -V` |
| PuTTY 의 `plink.exe` | **비밀번호** 인증을 쓸 때만 | `plink -V` |
| 파이썬 3.8+ | 소스로 돌릴 때만. exe 로 묶으면 필요 없다 | `python -V` |

윈도우의 `ssh.exe` 는 비밀번호를 비대화형으로 넣지 못한다. 그래서 비밀번호로
붙는 서버가 있으면 `plink.exe` 가 필요하다. **될 수 있으면 키 인증을 쓴다.**
비밀번호는 명령줄 인자로 넘어가므로 같은 PC 의 다른 사용자가 프로세스
목록에서 볼 수 있다.

OpenSSH 클라이언트가 없으면: 설정 → 앱 → 선택적 기능 → OpenSSH 클라이언트.

## 2. 받기 (쓰는 사람)

웹에서 받는다. **[서버] 화면 → [내 중계] → 「중계 프로그램 받기」**

받은 파일을 VDI 의 아무 폴더에나 둔다. 설치 과정이 없다. 파일 하나다.

> 화면에 sha256 이 함께 적혀 있다. 받은 파일이 같은 것인지 확인하려면
> VDI 에서 `certutil -hashfile relay.exe SHA256` 으로 맞춰 본다.

「아직 올라와 있지 않습니다」 라고 나오면 관리자가 아직 안 올린 것이다.

### 관리자가 한 번 해야 하는 일

`relay.exe` 를 만들어 웹에 올려 둔다. 인터넷이 되는 윈도우 PC 에서:

```
relay_agent\build.cmd      (더블클릭해도 된다)
```

`dist\relay.exe` 가 나온다. 그 파일을 웹에 올린다.
**[운영] → [중계 설정] → [중계 프로그램] → 올리기**

올리고 나면 그 뒤로는 사람들이 알아서 받아 간다. 관리자가 다시 할 일은 없다.

> VDI 에 파이썬이 깔려 있다면 exe 가 필요 없다. `relay.py` 파일 하나를 받아
> `python relay.py` 로 돌려도 똑같이 동작한다. (표준 라이브러리만 쓴다)

## 3. 등록 (VDI 에서 한 번)

웹의 **[서버] 화면 → [내 중계] → 「등록 코드 받기」** 를 누르면 두 줄이 나온다.
**내가 받은 코드로 등록한 중계는 내 중계가 된다.**

```
서버 주소 : https://chat.사내도메인
등록 코드 : 384901
```

VDI 에서:

```
> relay.exe register
중계 등록
----------------------------------------------------
관리자 화면(중계 설정)에서 받은 두 줄을 적어 주세요.

서버 주소 : https://chat.사내도메인
등록 코드 : 384901

등록했습니다. 설정 파일 : C:\Users\ops\AppData\Local\claude-relay\relay.json
이제 relay.exe (인자 없이) 를 실행해 두면 됩니다.
고칠 것이 생기면 웹만 고칩니다. 이 PC 는 다시 건드리지 않습니다.
```

사내 사설 인증서를 쓰면 `relay.exe register --insecure` 로 등록한다.
(그 뒤로도 그 설정이 유지된다)

**손으로 적는 줄은 이 둘뿐이다.** 서버가 열 대로 늘어도 VDI 를 다시 건드리지
않는다. 서버를 더하고 빼는 일, 누가 어디까지 쓸지 정하는 일은 전부 웹에서 한다.

VDI 를 새로 받았으면 새 코드를 받아 다시 등록하면 된다. 그때 내 예전 중계만
자동으로 끊긴다. (남의 중계는 건드리지 않는다)

등록 코드는 **한 번 쓰면 죽는다.** 10분이 지나면 만료된다. 새로 받으면 전에
뿌린 코드는 그 자리에서 죽는다.

## 5. 계속 돌리기

```
> relay.exe
[09:14:02] 중계 시작 · 서버 https://chat.사내도메인
```

창을 닫으면 멈춘다. VDI 가 재부팅돼도 살아 있게 하려면 **작업 스케줄러**에
등록한다.

```
schtasks /create /tn "claude-relay" /tr "C:\ops\relay.exe" /sc onstart /ru SYSTEM /rl HIGHEST
```

`/ru SYSTEM` 으로 돌리면 키 파일을 `C:\Windows\System32\config\systemprofile\.ssh\`
에서 찾는다. 사람 계정의 키를 쓰려면 `/ru <계정> /rp` 로 그 계정으로 돌린다.

## 6. 서버에 붙는 방법 두 가지

### 키 (권한다)

VDI 에 키를 두고 서버에 공개키를 넣는다.

```
> ssh-keygen -t ed25519 -f %USERPROFILE%\.ssh\ops-vdi-01 -C "ops-vdi-01"
> type %USERPROFILE%\.ssh\ops-vdi-01.pub
  (이 줄을 서버의 ~/.ssh/authorized_keys 에 넣는다)
```

웹의 「서버 추가」에서 인증을 **키**로 두고 **쓸 키 이름**에 `ops-vdi-01` 을
적는다. 키 **내용은 챗봇 서버에 올라가지 않는다.** 이름만 간다.

### 비밀번호

웹에 비밀번호를 넣어 두면 챗봇 서버가 암호화해서 저장하고, 중계가 일을 받아
갈 때만 복호화해서 실어 보낸다. 중계는 받아서 메모리에만 들고 쓰고 버린다.
디스크에 쓰지 않는다.

처음 붙기 전에 **호스트 키를 한 번 받아 둬야 한다.** `plink` 는 모르는 호스트
키를 비대화형으로 받아들이지 않는다.

```
> plink -ssh svc_ops@10.20.30.181
  The server's host key is not cached. ... Store key in cache? (y/n) y
```

## 7. 이 프로그램이 하는 일 / 안 하는 일

**한다**

- 챗봇 서버에서 할 일을 받아 `ssh.exe` / `plink.exe` 를 돌린다
- 터미널 화면을 그대로 올려 보낸다
- 받은 접속 정보는 메모리에만 두고 쓰고 버린다

**안 한다**

- 접속 정보를 디스크에 적지 않는다 (이 PC 에 남는 것은 중계 토큰 하나뿐)
- 명령을 스스로 만들지 않는다. 받은 것만 그대로 돌린다
- 챗봇 서버 말고 어디에도 연결하지 않는다
- 화면을 띄우지 않는다

---

## 8. 안 될 때

| 증상 | 볼 곳 |
|---|---|
| `챗봇 서버에 닿지 못했습니다` | 주소, 사내 프록시, 사설 인증서(`--insecure`) |
| `등록이 해제되었습니다` | 관리자가 중계를 끊었다. 등록 코드를 새로 받아 다시 등록 |
| `plink.exe 를 찾지 못했습니다` | PuTTY 설치, 또는 그 서버를 키 인증으로 바꾸기 |
| `키 파일이 없습니다` | `%USERPROFILE%\.ssh\<키 이름>` 확인. 작업 스케줄러의 실행 계정 확인 |
| 터미널이 `host key` 로 실패 | `plink -ssh 계정@주소` 를 한 번 실행해 호스트 키 받아 두기 |
| 웹에서 `내 VDI 의 중계가 붙어 있지 않습니다` | `relay.exe status` 로 연결 확인. 창이 닫혔는지 확인 |
| 남이 쓰는데 나만 안 됨 | 중계는 사람마다다. 내 VDI 에 내 중계가 떠 있어야 한다 |

로그는 화면에 그대로 찍힌다. 비밀번호와 키는 **어느 줄에도 찍지 않는다.**

---

## 9. 이 PC 에서 지우기

```
> relay.exe unregister
```

챗봇 서버 쪽 등록은 관리자 화면의 「이 중계 끊기」로 끊는다. 둘은 따로다.
한쪽만 지우면 다른 쪽은 그대로 남는다.
