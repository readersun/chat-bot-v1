# 사용자 클라이언트 (claude-term)

사내망 **밖**의 내 PC 에서 **진짜 PuTTY** 로 사내 서버에 붙는 프로그램이다.
VDI 에서 도는 중계(relay.exe)와는 다른 프로그램이다. 둘 다 있어야 한다.

```
 내 PC (바깥)                              챗봇 서버                 내 VDI              대상 서버
 ┌──────────────┐  127.0.0.1  ┌─────────────┐   HTTPS   ┌────────┐  HTTPS  ┌────────┐  TCP  ┌──────┐
 │ putty.exe    │────────────►│ claude-term │══════════►│ 터널    │◄════════│relay.exe│──────►│ :22  │
 └──────────────┘             └─────────────┘  (나감)   └────────┘  (나감)  └────────┘       └──────┘
          └──────────────────── SSH 는 여기서부터 여기까지 (PuTTY ↔ sshd) ──────────────────────┘
```

SSH 는 PuTTY 와 대상 서버의 sshd 사이에서 끝난다. claude-term · 챗봇 서버 ·
중계는 **암호문만** 옮긴다. 그래서

- 대상 서버 비밀번호는 **PuTTY 창에서 직접** 친다. 아무 곳에도 저장되지 않는다.
- 웹 콘솔과 달리 친 내용이 기록에 남지 않는다. 누가 · 언제 · 어느 서버 · 몇
  바이트만 남는다. 무엇을 쳤는지가 필요하면 대상 서버(auditd · sshd 로그)에서 남긴다.
- vi · top · Ctrl+C · 창 크기 · 색 — PuTTY 가 하는 일은 전부 그대로 된다.

## 1. 쓰려면 필요한 것

| 무엇 | 어디서 |
|---|---|
| 「셸 열기」 가 **웹 콘솔 + PuTTY 터널** | 관리자가 [운영] → [중계 설정] → [사용 허용] 에서 준다 |
| 내 VDI 에서 돌고 있는 중계 (relay.exe 0.2.0 이상) | [서버] → [내 중계] |
| 이 프로그램 (`claude-term.exe` + `putty.exe` 한 폴더) | [서버] → [내 클라이언트] → 「클라이언트 받기」 |

## 2. 등록 (내 PC 에서 한 번)

1. 받은 zip 을 아무 폴더에 푼다. `claude-term.exe` 와 `putty.exe` 가 **한 폴더**에
   있어야 한다(하위 폴더는 보지 않는다).
2. [서버] → [내 클라이언트] → 「등록 코드 받기」. 10분 안에 쓴다.
3. `claude-term.exe` 를 실행하고 챗봇 서버 주소와 등록 코드를 적는다.

키는 `%LOCALAPPDATA%\claude-term\client.json` 에 저장되고, 이 PC 의 내 계정만
읽을 수 있게 권한을 좁힌다. 이 키는 **나 자신**이다. 그래서 다음 경우에 죽는다.

- 웹에서 비밀번호를 바꿨을 때 (쿠키 로그인과 같은 규칙)
- 다른 PC 에서 다시 등록했을 때 (한 사람에 한 대)
- 웹에서 「등록 해제」 를 눌렀을 때 / 관리자가 계정을 정지했을 때

죽으면 프로그램이 등록 화면으로 돌아간다. 코드를 새로 받아 다시 등록한다.

## 3. 쓰기

- 서버를 고르고 **PuTTY 열기** (또는 두 번 누르기). PuTTY 창이 뜨면 비밀번호를 친다.
- **터널 닫기** 또는 PuTTY 창을 닫으면 터널이 닫힌다.
- **이 서버로 Claude** — 웹 채팅과 같은 대화다. `claude -p` 는 챗봇 서버에서 돌고
  구독도 서버의 것을 쓴다. 대화는 웹에서 이어서 볼 수 있다.
  - PuTTY 에서 드래그하면 복사된다 → 「PuTTY 에서 복사한 것을 붙여넣기」(Ctrl+Shift+V)
  - Claude 가 고른 변경 명령은 승인 카드로 온다. 「클립보드에 넣기」 로 PuTTY 에
    Shift+Insert 로 붙일 수 있다. **엔터는 사람이 친다.** Claude 가 PuTTY 에 대신
    타이핑하는 길은 만들지 않았다.

## 4. 끊길 때

PuTTY 는 암호화된 연결이 끊긴 것만 안다(`Network error ...`). **왜 끊겼는지는
claude-term 의 아래 상태줄**이 말한다.

| 상태줄 | 뜻 |
|---|---|
| VDI 중계가 멈췄습니다 | 내 VDI 의 relay.exe 가 꺼졌다. 바이트가 중계를 지나므로 터널도 끊긴다 |
| N분 동안 아무것도 지나가지 않아 닫았습니다 | 유휴 시간(기본 10분). PuTTY 의 keepalive 를 켜 두면 닫히지 않는다 |
| ... 허용이 해제되어 터널을 닫았습니다 | 관리자가 권한을 바꿨다 |
| 관리자가 ... 서버를 꺼서 터널을 닫았습니다 | 서버가 꺼졌다 |
| VDI 중계가 a.b.c.d:22 에 닿지 못했습니다 | 대상이 꺼졌거나 VDI 에서 그 포트로 못 나간다 |
| 띄운 PuTTY 가 아닌 다른 프로그램이 먼저 붙어 끊었습니다 | 내 PC 의 다른 프로그램이 그 포트에 먼저 붙었다 |

## 5. 확인할 것 (PuTTY 버전)

claude-term 은 PuTTY 를 이렇게 띄운다.

```
putty.exe -ssh -P <로컬 포트> -l <계정> -loghost <서버 이름> 127.0.0.1
```

`-loghost` 는 창 제목과 호스트 키를 `127.0.0.1` 대신 서버 이름으로 기억하게 한다.
받은 putty.exe 가 이 옵션을 모르면 [설정] 에서 끈다. 로컬 포트는 서버마다
정해져 있다(40000 + 서버 번호). 포트가 매번 바뀌면 열 때마다 호스트 키를 묻기 때문이다.

## 6. 만들기 (관리자가 한 번)

인터넷이 되는 윈도우 PC 에서 `client_app\build.cmd` 를 실행한다.
`dist\claude-term.exe` 와 `putty.exe` 를 **한 폴더에 넣고 그 둘만** zip 으로 묶어
[운영] → [중계 설정] → [사용자 클라이언트] 에 올린다.

표준 라이브러리만 쓴다(tkinter, urllib, http.client, socket). 파이썬이 있는 PC 라면
`python claude_term.py` 로도 돈다.
